# Reclamation

Read when the project is long-lived and the audit found no periodic
cleanup, or when the user asks how to keep the repaired harness from
decaying again. Edit-time sync catches drift as files change; periodic
reclamation catches what nobody edited. Installing the routine belongs to
the entropy layer; this file is what the plan item asks it for. [§5.2]
[§6.2]

## What each run hunts

- Stale paths and dead commands: run them, do not trust them.
- Rules the code now contradicts, and specs that drifted.
- One rule stated in two places.
- Content no entrypoint route reaches; triggers that can no longer fire.
- Thickness beyond what the five variables still justify: the thinning
  candidates, with their evidence.
- Open items carrying the project's harness-deviation label.

Every finding gets a disposition (update, reconnect, merge, thin, remove)
applied in the same run or recorded as a tracked item. Deleting stale
content is the goal, not a loss.

## Cadence

Choose by change velocity: monthly for fast-moving projects, quarterly for
slower ones. Anchor it to an event the team already has (a release, a
retrospective) so the routine has a trigger, and record the date of the
last run as an absolute date.

## Recommendation

Recommend a short dated section in a knowledge file (the hunt list, the
cadence, the anchor, the last run) for medium entropy grade; recommend a
cleanup project skill only at thick grade or when the hunt has project-
specific steps. Present both and let the user choose.
