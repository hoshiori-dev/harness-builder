# GitHub Workflow

Read when taking, creating, or finishing an issue or pull request, when a check
is red, or before any `gh` write. Host: github.com, repository
`hoshiori-dev/harness-builder`, public, organisation-owned with a single
maintainer. Remote settings: `.agents/knowledge/github/platform-settings.md`;
check jobs: `.agents/knowledge/github/checks.md`.

## Objects in use

| Object | Use |
|---|---|
| Issues | every unit of work; forms in `.github/ISSUE_TEMPLATE/` (`bug`, `feature`, `task`) set the type label |
| Labels | `type:*` (what), `area:*` (where: `skills`, `agents`, `harness`, `ci`, `docs`), `spec:skipped \| pending \| approved \| archived` (OpenSpec state, maintained by the `pr-labels` workflow; only `spec:approved` is added by a person), `dependencies`; defined in `.github/labels.json`, applied by the `labels` workflow on push to `main` (`just labels` shows drift) |
| Pull requests | the only path into `main`; draft first, template in `.github/pull_request_template.md` |
| Releases | one per `v*` tag, notes generated by `.github/release.yml`, archive attached by the release workflow |
| Pages | the docs site, deployed by the `docs` workflow from `main` |
| Not used | milestones, projects, discussions, wikis; add one only when something would be lost without it |

## The loop

1. Take an issue: `gh issue edit <n> --add-assignee @me`, then
   `gh issue develop -c <n>` (branch naming in `git-workflow.md`).
2. Open a draft PR at once with `Closes #<n>` and the OpenSpec change
   directory (or `spec-less: <reason>`); the draft is the claim and the log.
3. For a spec-carrying change, wait for `spec:approved` before tasks or code
   (`spec-workflow.md`).
4. Implement with task-level commits; keep `just check` green; push the one
   branch.
5. Run the behavioural tests, self-review, mark ready
   (`agent-authority.md`).
6. Review, archive on the branch, squash merge; the branch is deleted.

Every label, assignee, or state change is an explicit `gh` call; GitHub has
no slash commands. Non-interactive issue creation ignores forms: mirror the
form's `### <label>` headings in the body and pass `--label` explicitly.

## Confidentiality

Issues, PRs, commits, and CI logs are public. Never paste tokens, local paths
with user names, or session transcripts; betterleaks blocks commits locally
and CI scans every pushed commit. Session logs and handoff notes stay out of
the repository.

## Synchronization

| Pair | Owner | Trigger |
|---|---|---|
| `justfile` recipes ↔ `.github/workflows/*.yml` jobs ↔ `github/checks.md` | the change that edits any of them | adding, renaming, or removing a recipe or job |
| `.github/labels.json` ↔ `.github/release.yml` categories ↔ issue-form `labels:` ↔ the state names in `scripts/lib/pr_labels.ts` | the change that edits labels | any label rename |
| PR template headings and the "No secrets" item ↔ `scripts/check_pr.ts` | the change that edits either | rewording the template |
| `.github/CODEOWNERS` ↔ maintainers | the maintainer | a new maintainer |
