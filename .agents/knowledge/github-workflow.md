# GitHub Workflow

Read when taking, creating, or finishing an issue or pull request, when a check
is red, or before any `gh` write. Host: github.com, repository
`hoshiori-dev/harness-builder`, public, personal-account owner. Remote
settings are recorded in `.agents/knowledge/github/platform-settings.md`;
check jobs in `.agents/knowledge/github/checks.md`.

## Objects in use

| Object | Use |
|---|---|
| Issues | every unit of work; forms in `.github/ISSUE_TEMPLATE/` (`bug`, `feature`, `task`) set the type label |
| Labels | `type: *` (what), `area: *` (where), `spec: skipped | pending | approved | archived` (OpenSpec state, maintained by the `pr-labels` workflow; only `spec: approved` is added by a person), `dependencies`; defined in `.github/labels.json`, applied by the `labels` workflow on push to `main` (`just labels` shows drift locally) |
| Pull requests | the only path into `main`; draft first, template in `.github/pull_request_template.md` |
| Releases | one per `v*` tag, notes generated by `.github/release.yml`, archive attached by the release workflow |
| Not used | milestones, projects, discussions, wikis, issue types and fields (personal account) |

## The loop

1. Take an issue: assign yourself, create the branch with
   `gh issue develop -c <n>` (naming per `.agents/knowledge/git-workflow.md`).
2. Open a draft PR at once with `Closes #<n>` and the OpenSpec change
   directory (or `spec-less: <reason>`); the draft is the claim and the log.
3. Wait for `spec: approved` before writing tasks or code for a spec-carrying
   change (`.agents/knowledge/spec-workflow.md`).
4. Implement; keep `just check` green; push the single branch.
5. Self-review, then mark ready when the checklist is ticked and checks are
   green (`.agents/knowledge/agent-authority.md` sets the bar and says who may).
6. Review, archive the change on the branch, squash-merge; the branch is
   deleted on merge.

Every label, assignee, or state change is an explicit `gh` call; GitHub has no
slash commands. Non-interactive issue creation ignores forms: mirror the form's
`### <label>` headings in the body and pass `--label` explicitly.

## Confidentiality

Issues, PRs, commits, and CI logs are public. Never paste tokens, local paths
with user names, or session transcripts; betterleaks blocks commits and CI
scans every pushed commit.

## Synchronization

| Pair | Owner | Trigger |
|---|---|---|
| `justfile` recipes ↔ `.github/workflows/*.yml` jobs ↔ `github/checks.md` | the change that edits any of them | adding, renaming, or removing a recipe or job |
| `.github/labels.json` ↔ `.github/release.yml` categories ↔ issue-form `labels:` ↔ the state names in `scripts/lib/pr_labels.ts` | the change that edits labels | any label rename |
| PR template headings and the "No secrets" item ↔ `scripts/check_pr.ts` | the change that edits either | rewording the template |
| `.github/CODEOWNERS` ↔ repository owner | the template user, on creation | repository transfer or new maintainer |

## For template users

Creating a repository from this template copies files only. Set the remote
settings listed in `.agents/knowledge/github/platform-settings.md`, run
`just labels --apply`, and replace the owner in `.github/CODEOWNERS`.
